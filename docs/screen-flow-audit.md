# Rogue 5.4.4 screen-flow audit

The GUI starts in the initialized dungeon. `?` asks for a command key, and `*` lists command bindings. The play view reserves the top row for the latest message or active prompt, the middle rows for the map, and the bottom row for status.

| Area | Rogue 5.4.4 reference | GoRogue decision |
| --- | --- | --- |
| Start | [`main.c`](https://github.com/Davidslv/rogue/blob/cf9bd26/main.c) calls `new_level()` and `playit()` without a title menu. | Start in the already initialized `StateGame`; do not recreate the dungeon before the first turn. |
| Play regions | [`io.c`](https://github.com/Davidslv/rogue/blob/cf9bd26/io.c) puts messages on row 0, the map in the middle, and normally draws status at `STATLINE`. | Use the top row for the latest message or prompt, reserve the last row for status, and offset the map below the message row. This keeps the map visible without a separate message log. |
| Status | [`io.c`](https://github.com/Davidslv/rogue/blob/cf9bd26/io.c) prints dungeon level, gold, current and maximum HP, current and maximum strength, armor, experience level and points, and hunger state. [`rogue.doc.in`](https://github.com/Davidslv/rogue/blob/cf9bd26/rogue.doc.in) explains those fields. | Show the same fields from `Player` and `DungeonManager`. Display armor as `10 - GetTotalDefense()`. Omit hunger text when satisfied. Remove GoRogue's attack, defense, hunger percentage, equipment, and floor-marker fields from the status line. |
| Messages | [`io.c`](https://github.com/Davidslv/rogue/blob/cf9bd26/io.c) displays messages and uses `--More--` when it must pause before replacing a message. | Keep the latest message or prompt in the top row. GoRogue does not pause the command loop to acknowledge every replaced message. This avoids changing command timing as part of a display correction. |
| Help | [`command.c`](https://github.com/Davidslv/rogue/blob/cf9bd26/command.c) maps `?` to `help()`. [`rogue.doc.in`](https://github.com/Davidslv/rogue/blob/cf9bd26/rogue.doc.in) describes entering a key for its command explanation or `*` for the command list. | Keep help in the play view. A requested key displays its binding description; `*` displays the list. Help input never executes a gameplay command. |
| Death | [`rip.c`](https://github.com/Davidslv/rogue/blob/cf9bd26/rip.c) shows a death message or tombstone, then the score list and a final acknowledgement. | Show death details, then the existing GoRogue score and an acknowledgement. Do not add tombstone art or change death scoring. The sequence exits instead of returning to a title menu. |
| Victory | `rip.c` shows the total-winner message, values inventory, then displays the score. | Show congratulations, then the existing GoRogue score and an acknowledgement. Do not add inventory valuation or alter score rules. The sequence exits after acknowledgement. |

The `:` debug CLI, arrow-key movement, and wizard controls remain GoRogue conveniences. Save and load remain available through the CLI, and SIGHUP still creates a recovery save. The old title-menu route to the GUI save/load screen is removed because it conflicts with direct gameplay. [Issue #98](https://github.com/yuru-sha/gorogue/issues/98) tracks restoring GUI access to saved games without bringing back the title menu.
